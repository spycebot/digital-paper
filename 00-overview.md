# digital-paper Design Language System Overview

Created: 
Updated: 06 NOV 2026

## Purpose

The **digital-paper** Design Language System provided guidance and instructions for human designers and AI design and coding agents alike when developing digital assets.

This system will serve as a single source of truth with respect to elements of design including look and feel, graphics, animations, and media representations. **digital-paper** is an evolving work in progress, and the record of that progress is contained in this document.


### Scope

The scope of the **digital-paper** Design Language System is the digital domain, namely websites and apps, as well as social media assets.

At present, **digital-paper** has been applied to the following assets:

1. [shannonware.com](https://shannonware.com)
2. [Card Catalog Kanban](https://kanban.terzotech.net)
1. [SNG Safety Equipment Inspection](https://inspection.sng.ie)
1. [LinkedIn Posts](https://www.linkedin.com/in/shannon-ware-18a607288/)
1. [Instagram Posts](https://www.instagram.com/bearwaker)
1. [BlueSky Posts](https://bsky.app/profile/bearwaker.bsky.social)


### Intended Users

This design language system is intended for the following audiences engaged in developing assets for **digital-paper** projects.

1. Human digital asset designers
1. AI design and coding agents

### How to Use This Document

In the first instance, the repository holding this document is an endpoint that is easily passed to a coding agent as part of an instruction prompt. For example: "Develop a marking website hosting on AWS infrastructure that implements the digital-paper design language system (https://github.com/spycebot/digital-paper/edit/main/00-overview.md)".

In the second instance, this document collects and tracks the design decisions that have gone into **digital-paper**, allows us to further consider those decisions in depth, and provides a history of the design development process.

As a resource published to the web, it can be quickly and easily referenced throughout the design process. As a GitHub repository, it can be updated and extended, accepting potential contributions from anyone able to make a pull request. It can be branched by anyone who wants to use the ideas as a starting point for their own design system. And at the end of the day, it is a good bit of craic.
